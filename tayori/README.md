# たより(災害時安否通信アプリ)— フェーズ1 MVP

スマホ同士の Bluetooth(BLE)中継だけで安否メッセージを届ける、FEWC課題研究用の実験アプリです。
フェーズ1のゴールは **A→B→C の中継で、A から直接届かない C にメッセージが届くこと** です。

## フォルダ構成

```
tayori/
├── core/   中継ロジック(Android非依存の純Kotlin)+ 単体テスト
│   ├── Message.kt        メッセージの形(ID・宛先・ステータス・本文・TTL・Hop)
│   ├── PacketCodec.kt    メッセージ ⇔ バイト列 の変換
│   ├── Transport.kt      「通信路」の抽象(BLE と Fake を差し替える接点)
│   ├── RelayEngine.kt    中継の判断(重複排除・TTL・誰に渡すか)
│   └── ExperimentLog.kt  ログ項目とCSV形式
└── app/    Androidアプリ
    ├── BleTransport.kt   BLE(広告・スキャン・GATT)での Transport 実装
    ├── TayoriService.kt  常駐サービス(画面オフでも中継を続ける)
    ├── TayoriRuntime.kt  アプリ全体で1つの本体
    ├── CsvFileLog.kt     ログを端末内CSVに追記・書き出し
    └── MainActivity.kt   画面
```

**なぜ分けたか**: 中継ロジック(core)は BLE を一切知らず、`Transport` という窓口だけを使います。
テストでは偽の通信 `FakeTransport` に差し替えるので、実機が1台でも「13台が一列に並んだ状況」などをPC上で再現できます。

## 中継の仕組み

1. 送信者はメッセージを作り、近くの端末に渡す(近くに誰もいなければ、出会うまで持ち続ける)
2. 受け取った端末は、自分宛てなら表示して終わり。他人宛てなら手元に保持し、**まだ渡していない近くの端末**に渡す
3. **同じ Message ID は二度と中継しない**(重複排除)。受け取った相手・送信元には送り返さない
4. **TTL = 10**: 送信元は ttl=10 で送り、中継のたびに1減る。ttl=0 で受け取った端末は中継しない
   → 中継は最大10回、Hop数は最大11(A→B→C なら C での Hop は 2)

この「持ち歩いて、出会った人に渡す」方式を **蓄積・運搬・転送(store-carry-forward)** と呼びます。

## ビルドとインストール(Android Studio)

1. Android Studio で `tayori` フォルダを開く(`SNS` フォルダではなく、その中の `tayori`)
2. 初回は Gradle の同期が自動で走ります。`local.properties` が作られると `app` モジュールが読み込まれます
3. Galaxy を USB でつなぎ(開発者オプションの USB デバッグをオン)、▶ Run を押す
4. 他の実験機には、`Build > Build APK(s)` で作った APK(`app/build/outputs/apk/debug/app-debug.apk`)を送ってインストール

中継ロジックのテストだけなら、PC で `./gradlew :core:test` を実行します(Android SDK 不要)。

## 実験の手順(例)

1. 全端末で **日付と時刻を自動設定** にしておく(送信時刻と受信時刻は別の端末の時計で記録するため)
2. 各端末でアプリを開き、端末IDを `A` `B` `C` に設定して「IDを保存」
3. 「電池の最適化を解除」を押して許可(Galaxy は「設定 > バッテリー > バックグラウンドでの使用制限」で
   「スリープ状態のアプリ」に入っていないかも確認)
4. **連絡先コードを交換する**: 送る側(A)と受け取る側(C)が、②の連絡先コードを交換して「連絡先に追加」
   (QRコードを相手のカメラで読み取ってコピー → 貼り付け、またはLINEなどで送り合う)。
   メッセージは宛先の公開鍵で暗号化するので、コードを交換していない相手には送れない。中継役(B)は交換不要
5. 全端末で「中継を開始」→ 権限を許可
6. 前の試行のログが残っていれば「ログを消去」
7. A と C を電波が届かない距離に離し、B をその中間に置く
8. A で宛先 `C` を入れて送信 → C の「自分宛てに届いたメッセージ」に「本人確認済み」で表示され、Hop が 2 なら成功
9. 全端末で「CSVで書き出し」→ 3台分のCSVを1つにまとめて分析(中継役のCSVには送り主・状態は記録されない。Message ID で突き合わせる)

## ログ(CSV)の列

| 列 | 意味 |
|---|---|
| log_time_local / log_time_ms | その行を記録した時刻(読みやすい形式 / ミリ秒) |
| device_id | この端末のID |
| event | 出来事の種類(下表) |
| message_id | メッセージID |
| origin_id / dest_id | 送信元 / 宛先 |
| status | 無事・要救助・移動中 |
| peer_id | 相手端末(送り先・受け取り元・接触相手) |
| sent_at_ms | **送信時刻**(送信元でメッセージを作った時刻) |
| received_at_ms | **受信時刻**(この端末で受け取った時刻) |
| latency_ms | 受信時刻 − 送信時刻(端末間の時計のずれを含む) |
| hop | **Hop数** |
| ttl | 残りTTL |
| contact_count_total | この端末の **累計接触回数** |
| peer_contact_count | peer_id の相手との接触回数 |
| send_count_message | このメッセージをこの端末が **実際に送れた回数** |
| send_count_total | この端末の累計送信成功回数 |
| note | 補足 |

| event | 意味 |
|---|---|
| CREATED | 自分がメッセージを作った |
| CONTACT | 他端末と接触した(**送信の有無と無関係**) |
| SENT | 実際に送れた(相手の受信確認あり) |
| SEND_FAILED | 送ろうとして失敗した |
| RECEIVED | 他人宛てを受け取り、中継用に保持した |
| DELIVERED | 自分宛てが届いた |
| DUPLICATE | 既に受け取った Message ID が再び届いた(破棄) |
| TTL_EXPIRED | TTL切れなので中継しない |
| BUFFER_EVICTED | 保持上限(500件)を超えて捨てた(一番多く持ち込んだ相手のものから) |
| INVALID_PACKET | 解読できないデータが届いた |
| REJECTED | ルール違反で捨てた(不正なID・古すぎる・未来の時刻・受信しすぎ。理由は note 列) |
| UNREADABLE | 自分宛てだが開封できなかった(自分の鍵で暗号化されていない・書き換えられている) |
| SPOOFED | 登録済みの人を名乗っているのに署名が合わない(なりすまし)ので捨てた |

### 「接触」と「送信」の定義

- **接触**: スキャンで相手が見えたとき。ただし **10秒以上見えていなかった相手** が再び見えたときだけ1回と数えます
  (BLEのスキャン結果は同じ相手について1秒に何度も来るため)。この10秒は `RelayConfig.contactGapMs` で変更できます。
- **送信**: 相手の GATT サーバーへの書き込みが成功した回数。接触しても「渡すものがない」「既に渡した」「失敗した」場合は増えません。

## 機種差で動かない可能性がある箇所

コード内では `【機種差】` `【OS制限】` というコメントで印を付けています。主なものは次のとおりです。

| 箇所 | 起こりうること | アプリの表示 |
|---|---|---|
| BLE広告(ペリフェラル機能) | 非対応機種は他から見つけてもらえない=**受信役になれない**(送信・中継の書き込みはできる) | 「広告: ×」と警告 |
| GATTサーバー | 開けない機種・状態がある → 受信役になれない | 「受信窓口: ×」と警告 |
| スキャン応答 | 返さない/遅い機種だと相手が端末IDを読めない | 相手の「近くの端末」に出てこない |
| MTU交渉 | 応じない機種がある → 分割書き込みで送るので通常は問題なし | — |
| 接続エラー133 | 多くの機種で一時的に出る → 5秒後に自動再試行 | ログに SEND_FAILED |
| 省電力機能(特にGalaxy) | 裏で動くアプリを止める | 通知が消える・接触が記録されない |
| Android 11以前 | 位置情報スイッチがオフだとスキャン結果0件 | 警告を表示 |
| OSのスキャン制限 | 30秒に5回超の開始で黙って停止 / 30分で低頻度化 | アプリ側で回避済み |

## 確認が必要な点

- **実機ではまだ動かしていません。** このコードは開発環境で、中継ロジックの単体テスト(18件)と、
  Android 15 のフレームワークに対するコンパイル検査まで確認しています。APK のビルド・実機での BLE 動作は未確認です。
- Android Gradle Plugin のバージョン(`app/build.gradle.kts` の 8.13.0)は開発環境から取得を確認できていません。
  Android Studio で同期エラーになったら、表示される推奨バージョンに変えてください。
- 「接触」を10秒の空白で区切る定義は仮決めです。研究の定義に合わせて調整してください。
- 端末間の時計のずれは補正していません。遅延を厳密に測る場合は、各端末の時刻ずれを別途記録してください。
- アプリを停止→再開しても受信済みIDは覚えていますが、**アプリのプロセスが終了すると忘れます**
  (中継用に持っているメッセージも消えます)。試行ごとにアプリを入れ直す必要はありません。

## 安全のための仕組み

安全性の検証(悪意ある端末を模したテスト)で見つかった問題への対策です。対応するテストは `core/src/test/.../SecurityTest.kt`。

| 問題 | 対策 |
|---|---|
| 本文が丸見え | 中身(送り主・状態・本文)を宛先の公開鍵で暗号化(P-256 ECDH + AES-256-GCM)。中継役には宛先IDと作成時刻しか見えない |
| なりすまし | 送り主が秘密鍵で署名(ECDSA)。登録済みの人を名乗る偽物は `SPOOFED` で捨てる。未登録の送り主は「本人か確認できません」と表示 |
| 封筒の書き換え | 宛先・作成時刻も暗号の認証対象にしているので、中継役が書き換えると開封できない |
| 追跡 | 周りに知らせるIDは端末IDではなく、15分ごとに変わるランダムな一時ID |
| TTLの水増し | 受け取ったTTLが10を超えていたら10に切り詰める |
| 不正なID・古い/未来のメッセージ | IDの形式、ホップ数、作成時刻(24時間より古い・1時間より未来)を確認して捨てる |
| 大量送信・押し出し | 1つの相手から1分30件まで。満杯時は一番多く持ち込んだ相手のものから捨て、自分のメッセージは捨てない |
| 記憶・記録の溜まりすぎ | 受信済みIDは2万件・24時間で忘れる。記録ファイルは20MBで止める |
| 巨大なデータ | 1件512バイトまで。BLEの分割受信も512バイト・同時8台まで、1台あたり10秒で8KBまで |
| CSVの数式実行 | `=` `+` `-` `@` で始まる文字の値は先頭に `'` を付けて、Excelで数式として動かないようにする |
| 署名鍵の公開 | 実験版(公開の練習用鍵)は `com.zavier.tayori.exp` という別アプリ。公開版は環境変数で渡す非公開の鍵でだけ署名する |
| 不正曲線攻撃 | 相手から届いた公開鍵の点が曲線の上にあるかを必ず確認する |

**残っている限界**
- 受信窓口は、見知らぬ人同士で使う仕組み上、どの機器からでも書き込める(上の制限で被害を抑えている)
- 宛先IDと作成時刻は中継役に見える(届けるために必要)
- 一時IDを次々に変える相手からの大量送信は、完全には防げない
- 秘密鍵はアプリ専用の保存領域にある(端末を分解・root化されると読まれうる)
- 一時IDが15分ごとに変わるので、「同じ相手との接触回数」は15分ごとに別の相手として数えられる

## スコープ外(フェーズ1ではやらない)

Supabase連携、ゲートウェイ機能、アカウント登録、プッシュ通知、iOS対応、グループ宛先。
暗号化と署名は入れましたが、専門家による安全性の診断は受けていません。実験以外の用途(実際の個人情報)には使わないでください。
